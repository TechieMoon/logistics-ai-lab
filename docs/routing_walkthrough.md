# 경로 최적화 코드 읽기와 실험 해석

이 문서는 `src/logistics_ai/routing.py`와 `scripts/train_routing.py`의 실제 구현을 설명한다. 합성 CVRP를 풀면서 그래프 표현 학습, 강화학습, 제약 검증, 고전 알고리즘 비교를 연습하는 소규모 프로젝트다. 실제 도로·교통·기업 데이터로 검증한 시스템은 아니다.

## 1. 무엇을 최소화하는가

고객은 $1,\dots,N$, 물류 거점은 $0$이다. 고객 $i$의 좌표를 $x_i\in\mathbb{R}^2$, 수요를 $q_i$, 차량 용량을 $C$라 둔다. 같은 용량의 차량을 필요한 만큼 사용할 수 있다.

한 차량의 경로는 `[0, 고객, ..., 고객, 0]`이고, 목적함수는 모든 경로의 유클리드 거리 합이다.

$$
L(\mathcal{R}) = \sum_{r\in\mathcal{R}}\sum_{t=0}^{|r|-2}\lVert x_{r_t}-x_{r_{t+1}}\rVert_2
$$

제약은 다음과 같다.

- 각 고객은 정확히 한 번 방문한다.
- 각 경로는 거점에서 출발하여 거점으로 돌아온다.
- 경로별 고객 수요 합은 차량 용량을 넘지 않는다.

거리에는 **마지막 고객에서 거점으로 돌아오는 구간**도 들어간다. 차량 대수를 목적함수에 별도로 벌점으로 넣지는 않는다. 제한된 차량 대수, 배송 시간창, 도로망, 혼잡도, 운전자 휴식은 구현하지 않았다.

`generate_instance`의 기본값은 고객 15명, 용량 30이다. 고객 좌표는 단위 정사각형에서 균등하게 뽑고 거점은 `(0.5, 0.5)`로 고정한다. 수요는 1~9의 정수이며 용량이 작으면 상한도 줄인다. 따라서 결과의 거리 단위는 **좌표 단위**이고 km나 운송비로 바꿔 말할 수 없다.

## 2. 알고리즘과 검증기를 분리한 이유

`CVRPInstance`는 좌표·수요·용량의 형태와 유효성을 확인한다. `RouteSolution`은 경로, 거리, 검증 여부와 진단 정보를 담는다.

`validate_routes`는 알고리즘 내부의 `visited` 상태나 누적 비용을 신뢰하지 않고, 반환된 경로 목록을 NumPy로 다시 확인한다. 고객 누락·중복, 거점 누락, 경로 중간 거점, 범위 밖 고객 번호와 용량 초과를 찾고 거리를 재계산한다. 정책 출력이 유효하지 않으면 `solve_with_policy`는 실패를 명시적으로 알린다.

예를 들어 수요 `[0, 2, 2, 1]`, 용량 3인 경우 `[[0, 1, 0], [0, 2, 3, 0]]`은 유효하지만 `[[0, 1, 2, 3, 0]]`은 적재량 5로 용량을 초과한다. 이 검증은 모델이 높은 보상을 받더라도 배송을 빼먹은 결과를 좋은 결과로 오인하지 않게 한다.

## 3. 비교 기준: 최근접 이웃과 경로 내부 2-opt

`nearest_neighbor`는 현재 위치에서 가장 가까운 **미방문·적재 가능한 고객**을 고른다. 더 이상 적재 가능한 고객이 없으면 거점으로 돌아가 다음 차량을 시작한다. 같은 거리이면 고객 번호로 순서를 정해 결과를 재현한다.

`two_opt`는 각 차량에 이미 배정된 고객 집합을 그대로 둔다. 경로에서 두 간선을 골라 사이 구간을 뒤집었을 때 거리가 엄격히 줄어드는 경우만 반영한다. 예를 들어 기존 간선이 $(a,b),(c,d)$라면 다음 차이를 계산한다.

$$
\Delta = d(a,c)+d(b,d)-d(a,b)-d(c,d)
$$

$\Delta<-10^{-10}$이면 구간을 뒤집는다. 각 차량 안에서 고객 순서만 바꾸므로 고객 수요 합과 차량 배정은 유지된다. 차량 간 고객 교환, 다른 차량으로의 재배정, 전역 최적화는 하지 않는다. 이 구현에서 `nearest_neighbor_2opt`가 최근접 이웃보다 나빠지지 않는 것은 학습 성능이 아니라 **엄격히 개선되는 이동만 허용한 알고리즘의 성질**이다.

## 4. GNN이 실제로 계산하는 내용

`RoutingPolicy`의 기본 은닉 차원은 64, 메시지 전달 층 수는 2다. 노드 초기 입력은 좌표 2개, 용량으로 나눈 수요, 거점 여부의 총 4개 값이다.

$$
h_i^{(0)} = \operatorname{Linear}([x_i^x,x_i^y,q_i/C,\mathbb{1}(i=0)])
$$

`MessagePassingLayer`는 모든 노드 쌍을 연결한 조밀한 그래프에서 거리와 표현 벡터로 주의 가중치를 만든다.

$$
\alpha_{ij}=\operatorname{softmax}_j\left(\frac{(Qh_i)^T(Kh_j)}{\sqrt{H}}-\operatorname{softplus}(\beta)d(i,j)\right)
$$

$$
m_i=\sum_j\alpha_{ij}Vh_j,\qquad
h_i'=\operatorname{LayerNorm}\left(h_i+\operatorname{MLP}([h_i,m_i])\right)
$$

즉, 고객 하나의 좌표만 보는 대신 다른 고객의 표현을 가중 합산하여 해당 고객의 표현을 갱신한다. 이 메시지 전달과 파라미터 학습이 GNN이라고 부르는 근거다. 별도의 PyG 라이브러리를 쓰지 않고 PyTorch의 행렬 연산으로 구현했다.

디코더는 현재 고객 표현, 전체 노드 표현의 평균, 남은 적재량을 입력으로 다음 방문지의 점수를 만든다. 고객별 추가 입력은 다음 7개다.

1. 현재 위치 기준 x 차이
2. 현재 위치 기준 y 차이
3. 현재 위치에서의 거리
4. 거점에서의 거리
5. 용량으로 나눈 고객 수요
6. 현재 남은 적재량 비율
7. 거점 여부

방문한 고객과 용량을 넘는 고객의 점수는 `-inf`로 가린다. 현재 거점에 있으면 다시 거점으로 가는 행동도 막는다. 모든 배송이 끝난 배치 행에는 거점 행동만 남겨 비용 0으로 채운다. 고객 방문 사이에 거점이 최대 한 번 들어갈 수 있으므로 `2*N+1`개의 행동 슬롯이면 충분하다.

학습할 때는 점수의 softmax 확률로 행동을 표본 추출하고, 추론할 때는 최고 점수 행동을 고르는 greedy 방식이다. 학습 정책은 아직 적재 가능한 고객이 있더라도 먼저 거점으로 돌아갈 수 있다. 최근접 이웃 기준 알고리즘은 적재 가능한 고객이 없어질 때만 돌아간다.

### 수작업 거리 사전지식도 들어 있다

다음 방문지 점수에는 `-softplus(distance_weight) * distance`가 들어간다. 거리 가중치의 초기 파라미터는 4.0이다. 불필요한 거점 복귀를 줄이는 학습 가능한 거점 벌점도 있다. 따라서 모델은 처음부터 가까운 고객을 선호하는 **사람이 넣은 사전지식**을 갖는다.

이 프로젝트를 “아무 정보 없이 신경망이 최적 경로를 발견했다”라고 설명하면 부정확하다. 메시지 전달 층과 디코더는 학습되지만 기하학적 거리 선호도 함께 사용한다. `initial_policy`와 학습 후 정책을 동일한 평가 사례에서 비교하는 이유가 여기에 있다.

## 5. REINFORCE 손실의 부호 이해하기

정책 파라미터를 $\theta$, 표본 추출한 전체 경로를 $\pi$라 하자. 최소화하려는 것은 기대 거리다.

$$
J(\theta)=\mathbb{E}_{\pi\sim p_\theta}[L(\pi)]
$$

학습 스크립트는 같은 문제를 현재 정책의 greedy 방식으로 풀어 기준 거리 $b$를 만든다. 이 기준은 `torch.no_grad()` 안에서 계산한다. 표본 추출한 경로의 거리와 기준 거리의 차이가 advantage다.

```python
advantage = (costs - baseline_cost).detach()
loss = (advantage * log_probability).mean()
```

여기서 `log_probability`는 선택한 모든 행동의 로그 확률 합이다.

$$
\mathcal{L}=\frac1B\sum_{s=1}^{B}(L(\pi_s)-b_s)\sum_t\log p_\theta(a_{s,t}\mid s_t)
$$

- 표본 경로가 기준보다 길면 `advantage > 0`이다. 경사하강은 해당 경로의 로그 확률을 낮추는 방향으로 작용한다.
- 표본 경로가 기준보다 짧으면 `advantage < 0`이다. 경사하강은 해당 경로의 로그 확률을 높이는 방향으로 작용한다.

보상을 $R=-L$로 두고 보상을 최대화하는 REINFORCE와 같은 부호 관계다. 거리와 기준값을 `detach()`하여 경로 길이를 통해 직접 미분하지 않고, 행동 로그 확률을 통해 정책을 갱신한다. 같은 입력의 greedy 해를 기준으로 쓰는 방식은 self-critical baseline이며, 다른 논문의 별도 고정 rollout 모델이나 통계 검정 절차까지 재현한 구현은 아니다.

`reinforce_loss`는 음수가 될 수도 있다. 수치가 더 작아졌다는 사실만으로 배송 거리가 좋아졌다고 말하면 안 된다. 실제 거리와 검증 집합 성능을 함께 봐야 한다.

## 6. 학습·검증·평가가 섞이지 않게 한 구조

기본 `seed=42`일 때 난수 시드 구간은 다음 원칙으로 분리한다.

- 학습: `42 * 1,000,000,000`부터 시작하고 배치마다 새로운 시드를 사용한다.
- 검증: 학습 시작 시드에 `100,000,000`을 더한 구간이다.
- 최종 평가: 학습 시작 시드에 `200,000,000`을 더한 구간이다.

실제 범위와 사례 수는 `metrics.json`의 `data.seed_ranges_inclusive`에 저장된다. 검증 평균 거리가 가장 낮은 **한 번 이상 갱신한 모델**을 선택하고, 최종 평가 사례는 선택이 끝난 뒤 생성한다. 같은 최종 평가 사례를 모든 알고리즘에 사용한다.

평가 결과를 본 후 학습 횟수나 모델을 계속 바꾸면 그 평가 집합은 개발 과정에 사용한 집합이 된다. 추가 실험에서는 기존 결과를 숨기거나 좋은 숫자만 골라 쓰지 말고, 변경 이유·설정을 기록하고 별도의 최종 평가 시드를 확보해야 한다.

trace의 `sampled_distance`는 매 단계 새로운 학습 사례에서 측정한 확률적 경로 길이다. `greedy_baseline_distance`와 차이가 나는 것은 자연스럽다. `validation_distance`는 첫 단계, 정해진 간격, 마지막 단계에서만 채워진다. 빈 칸은 누락 실험이 아니라 해당 단계에서 별도 검증을 하지 않았다는 뜻이다. `gradient_norm_before_clip`은 norm 1.0으로 제한하기 전의 값이다.

`training.parameter_change_l2 > 0`은 초기값과 저장된 가중치가 달라졌다는 증거다. 테스트의 유한한 비영 gradient 확인 및 실제 optimizer 갱신과 함께 학습 경로가 작동함을 확인할 수 있다. **가중치 변화 자체는 성능 개선의 증거가 아니다.** 성능은 평가 집합의 거리로 판단한다.

평가의 `trained_improvement_pct_vs_initial`은 다음 계산이다.

$$
100\times\frac{\text{초기 정책 평균 거리}-\text{학습 정책 평균 거리}}{\text{초기 정책 평균 거리}}
$$

양수는 해당 평가 집합에서 거리가 줄었다는 뜻이며, 음수는 늘었다는 뜻이다. 최근접 이웃 대비 개선율도 같은 방식으로 계산한다. `initial_policy`, `gnn_reinforce`, `nearest_neighbor_2opt`, `gnn_reinforce_2opt`를 구분해 읽어야 한다. 후처리 효과를 신경망 자체의 성능으로 말하면 안 된다.

각 방법의 시간은 예열 후 사례 하나씩 측정한다. 모델 로딩 시간은 제외하고 경로 생성과 내부 유효성 검사를 포함한다. `*_2opt` 시간에는 기반 경로 생성 시간도 더한다. GPU 정책과 CPU 고전 알고리즘은 실행 장치가 다르므로 시간과 장치를 함께 보고한다. 학습 비용과 추론 비용도 구분한다.

### 저장된 2026-09-20 실행 결과를 읽는 예

현재 `metrics.json`에는 RTX 3060에서 400단계, 배치 128로 학습한 결과가 저장되어 있다. 학습 사례는 51,200개, 검증 사례는 64개, 최종 평가 사례는 128개다. 학습 시간은 약 64.30초이고 검증 기준으로 360단계 모델이 선택되었다. 모든 비교 방법의 경로 유효율은 100%였다.

| 방법 | 평균 거리 | 평균 차량 수 | 평균 추론 시간 |
|---|---:|---:|---:|
| 최근접 이웃 | 5.5826 | 2.9922 | 0.37 ms |
| 최근접 이웃 + 2-opt | 5.3410 | 2.9922 | 0.57 ms |
| 학습 전 정책 | 5.4533 | 3.1953 | 44.71 ms |
| 학습 정책 | 5.0010 | 3.6406 | 44.76 ms |
| 학습 정책 + 2-opt | 4.8670 | 3.6406 | 44.97 ms |

학습 정책의 평균 거리는 학습 전보다 8.29%, 최근접 이웃보다 10.42% 짧았다. 반면 최근접 이웃보다 평균 차량 수가 늘고 추론도 느렸다. 현재 목적함수에 차량별 고정 운행비가 없기 때문에 **짧은 거리와 적은 차량 수가 같은 목표가 아님**을 보여준다. “운영비 10.42% 절감”이나 “실제 물류 효율 10.42% 개선”으로 바꾸어 표현해서는 안 된다. 보고할 수 있는 결과는 이 합성 분포와 이 목적함수에서 측정한 거리 감소다.

추가 실험으로 차량별 고정비 $\lambda$를 포함한 $L+\lambda\cdot\lvert\mathcal{R}\rvert$를 학습할 수 있지만, 이는 아직 구현·검증하지 않은 별도 목표다. 기존 숫자를 그대로 해당 목표의 결과로 사용할 수 없다. 위 표 역시 단일 설정의 실행 결과이며 여러 난수 초기화에 걸친 통계적 우월성을 입증한 것은 아니다.

```powershell
.\.venv\Scripts\python.exe scripts\train_routing.py --device cuda --steps 400 --batch-size 128 --nodes 15
```

두 번째 명령은 기존 기본 산출물을 갱신한다. 설정을 비교하는 추가 실험은 `--output artifacts/routing_experiment_02`처럼 별도 경로로 저장한다. 검증 사례를 고르는 용도와 최종 평가 보고 용도를 구분하고, 이미 본 평가 결과를 새로운 독립 평가인 것처럼 소개하지 않는다.

검증 테스트에는 용량 초과, 중복·누락 방문, 거점 규칙, 귀환 거리, 재현 가능한 데이터 생성, 2-opt 개선, 실제 gradient 갱신, 저장한 체크포인트 추론이 포함된다. 유효한 해를 만든다는 테스트와 최적해를 찾았다는 증명은 서로 다르다. 이 프로젝트에는 최적해 비교기가 없으므로 optimality gap을 보고하지 않는다.

## 9. 면접에서 설명할 수 있어야 하는 경계

“합성 물류 문제에서 거리와 용량 제약을 정의하고, 메시지 전달 기반 정책을 REINFORCE로 학습했습니다. 같은 평가 사례에서 최근접 이웃과 2-opt를 비교하고, 출력 경로는 별도 검증기로 다시 확인했습니다. 모델에는 거리 선호 사전지식이 들어가므로 초기 정책과의 비교도 기록했습니다. 실제 개선 여부와 수치는 저장된 실행 결과를 근거로 설명하겠습니다.”

여기에 실제 `metrics.json`의 결과를 확인한 뒤 정확한 숫자를 붙인다. 모델이 고전 알고리즘보다 뒤지면 그 결과를 그대로 설명하고 데이터 분포, 훈련량, 정책 표현, 후처리 범위 등 가능한 원인을 다음 실험의 가설로 제시한다. 실행 전에 성능 우위를 보장하지 않는다.

참고한 1차 자료는 [Attention, Learn to Solve Routing Problems!](https://arxiv.org/abs/1803.08475)와 [PyTorch의 확률분포·REINFORCE 설명](https://docs.pytorch.org/docs/stable/distributions.html)이다. 본 구현은 논문의 영감을 받은 교육용 축소 구현으로, 논문의 성능이나 전체 실험 조건을 재현했다고 주장하지 않는다.
