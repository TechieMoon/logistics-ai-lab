## 두 개의 데이터 흐름

RAG 흐름은 `정책 문서 → 분할/색인 → 질문 검색 → 근거 선택 → 응답 생성 또는 근거 제시 → 인용 확인`입니다. 검색은 관련 문서를 찾고 생성은 문장을 만듭니다. 검색이 맞아도 답이 틀릴 수 있고, 답이 그럴듯해도 근거가 없을 수 있습니다. 외부 문서를 이용하는 생성 모델의 기본 발상은 [Lewis 등, RAG 원 논문](https://arxiv.org/abs/2005.11401)을 참고하세요. 이 저장소는 원 논문의 모든 학습·검색 구조를 재현한다는 주장을 하지 않습니다.

경로 흐름은 `좌표·수요·용량 → 노드/간선 표현 → 정책 점수 → 가능한 행동만 남김 → 방문/창고 복귀 → 거리 계산 → 학습 또는 평가`입니다. GNN은 주변 노드 정보를 합쳐 노드 표현을 갱신합니다. RL은 선택 결과의 비용을 이용해 정책을 바꿉니다. 그래프 표현 학습은 [GraphSAGE 논문](https://arxiv.org/abs/1706.02216), 학습 기반 경로 탐색은 [Kool 등 논문](https://arxiv.org/abs/1803.08475)을 개념 참고로 읽습니다. 저장소의 구현과 논문 알고리즘의 차이를 찾아내는 것도 학습입니다.

## 꼭 이해할 수식

**CVRP 거리 비용**: 각 차량이 `창고→고객들→창고`로 이동한 간선 거리를 모두 더합니다. 각 고객은 한 번 방문하고 한 경로에 실리는 수요 합은 용량 이하여야 합니다. 수요를 쪼개지 않는 설정에서는 한 고객의 수요가 차량 용량보다 크면 입력 자체가 불가능합니다.

**최근접 대비 변화율**: `100 × (학습정책 거리 - 최근접 거리) / 최근접 거리`. 음수는 거리 감소, 양수는 거리 증가입니다. 보고서가 감소율을 쓰면 부호가 반대이므로 분모와 부호를 확인하세요. 최적해를 구하지 않았다면 이것은 최적성 gap이 아닙니다.

현재 [실행 결과](../artifacts/routing/metrics.json)의 감소율은 반대 부호인 `100 × (기준선 거리 - 정책 거리) / 기준선 거리`입니다. 테스트 128개에서 최근접 대비 거리 감소는 10.42%, 학습 전 정책 대비 감소는 8.29%입니다. 동시에 평균 경로 수는 최근접 2.99개에서 학습정책 3.64개로 늘었습니다. 차량 수 상한·고정비가 없는 거리 최소화의 결과이므로 실제 운영비 절감이라고 말하지 않습니다. 8일차에는 거리와 경로 수를 함께 읽고, 차량 수 비용을 넣으면 어떤 의사결정이 달라질지 설명하세요. 경로 수는 코드상 `vehicles_used`로 기록되지만 실제 차량 재사용·시간 계획은 구현하지 않았습니다.

**정책경사**: 비용을 최소화하는 관점에서는 `E[(C - b) × log πθ(선택한 경로)]` 형태의 surrogate loss를 gradient descent로 낮춥니다. `C`는 거리 비용, `b`는 분산을 줄이는 baseline입니다. 같은 상태의 다른 행동이 평균적으로 더 좋았다면 현재 선택의 확률을 낮추는 방향이 됩니다. 보상 `R = -C`로 쓰는 구현은 부호가 달라집니다. 실제 코드가 어떤 관점인지 확인해야 합니다.

baseline은 nearest-neighbor 같은 비교 알고리즘과 이름이 같아도 역할이 다릅니다. RL baseline은 gradient의 분산 감소에 쓰이고, 평가 기준선은 성능 비교에 씁니다. baseline을 다른 경로의 gradient까지 역전파하지 않도록 detach하는지 확인합니다.

**Retrieval recall@k**: 질문에 필요한 정답 문서 중 상위 k개 검색 결과가 얼마나 포함하는지를 측정합니다. 정답 문서가 하나인 데이터에서 '상위 k 안에 정답이 있는 질문 비율'은 hit rate@k와 같습니다. 이 수치를 답변 정확도로 부르지 않습니다.

현재 라우팅 정책은 좌표 2개·용량으로 정규화한 수요·창고 여부의 **4개 입력 특징**을 사용합니다. 거리 기반 prior와 창고 복귀 penalty도 포함하므로, 결과가 좋아졌다고 전부 RL의 효과라고 해석할 수 없습니다. 학습 전 정책과 학습 후 정책 비교가 이 영향을 구분하는 데 필요합니다. 학습 baseline은 별도 critic이 아니라 같은 정책의 greedy 경로 비용입니다. API의 학습 경로 추론은 CPU를 사용하고, CUDA 학습은 학습 스크립트에서 수행합니다.

현재 RAG의 `support_score`는 상위 검색 결과의 **IDF 가중 질의 토큰 포함률 중 최댓값**입니다. dense 유사도나 정답 확률이 아닙니다. dev 질문으로 threshold를 고르며 `score > threshold`일 때 근거를 제시합니다. 낮은 점수면 동의어 질문도 거절할 수 있고, 높은 점수라도 숫자·예외 조건이 없는 문서일 수 있습니다. E5는 사전학습 임베딩 추론, Qwen은 선택적 생성 추론에 사용하며 두 모델 모두 이 프로젝트에서 새로 학습했다는 의미가 아닙니다. 구현 사용법은 [E5 모델 카드](https://huggingface.co/intfloat/multilingual-e5-small)와 [Qwen 모델 카드](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct)를 참고합니다.

README의 실행 명령이 호출하는 시작점부터 다음을 찾고 파일명·함수명·설명 한 줄을 개인 학습 노트에 적습니다. 함수 이름을 외우는 것보다 데이터가 바뀌는 지점을 찾는 것이 중요합니다.

1. seed를 설정하고 합성 좌표와 수요를 만드는 곳. 학습·평가 seed가 어떻게 다른가?
2. 유효하지 않은 방문지를 마스킹하는 곳. 고객 수요가 남은 용량과 같으면 방문 가능한가?
3. 창고 복귀 때 남은 용량을 초기화하는 곳. 마지막 창고 복귀 비용이 빠지지 않는가?
4. GNN의 이웃 집계와 정책 점수를 계산하는 곳. 노드마다 독립 MLP만 실행하는 부분과 어떻게 구별하는가?
5. 샘플링과 argmax를 선택하는 곳. 학습 때와 평가 때 왜 다르게 쓰는가?
6. loss.backward(), optimizer.step(), gradient 초기화가 있는 곳. 각각 어떤 상태를 바꾸는가?
7. 검색문서 ID를 생성 결과에 연결하는 곳. 문서 ID가 맞으면 사실성도 보장되는가?
8. 응답 보류를 결정하는 곳. 임계값을 바꾸면 오답과 과도한 거부 사이의 관계가 어떻게 바뀌는가?
9. 실제 GPU 텐서 연산과 모델 생성 코드. 'cuda 사용 가능' 출력만 있는 것과 어떻게 구분하는가?
10. 결과 파일을 저장하는 곳. 실행 설정·시간·seed·모델 revision을 다시 확인할 수 있는가?

## AI 도구를 사용하며 자기 역량으로 만드는 법

최초 구현은 AI 지원으로 작성될 수 있습니다. 코드 작성 지원과 본인의 검증·이해·개선은 구분해서 기록하세요. 면접에서 아직 읽지 않은 모듈을 직접 설계했다고 설명하면 안 됩니다.

매일 `질문 → 내가 먼저 세운 가설 → AI 제안 → 검증 방법 → 실제 관찰 → 내가 바꾼 것`을 6줄로 남깁니다. 공개 로그에는 개인 정보, 토큰, 채용 지원서 내용, 로컬 사용자 경로를 넣지 않습니다. 오답을 수정한 기록은 완벽한 첫 결과보다 문제 해결 능력을 설명하기 좋습니다.

직접 해 볼 작은 개선 예시는 다음과 같습니다. 구현 여부를 먼저 확인하고 이미 있는 기능이면 다른 것을 선택하세요.

- RAG 평가에 동의어 질문과 근거 없는 숫자 질문을 추가하고 실패 원인을 분석하기.
- 라우팅의 '남은 용량과 수요가 정확히 같은 고객' 경계 조건을 검증하기.
- node 수나 수요 분포를 바꿔 학습 분포 밖에서 성능이 떨어지는지 관찰하기.
- 경로 시각화에서 창고 복귀와 차량별 수요 합을 표시하기.

실험은 한 번에 한 변수를 바꿉니다. 좋은 결과만 남기지 않고 실패한 설정도 보존합니다. 여러 GPU·버전 간 완전한 재현이 보장되지는 않으므로 실제 환경과 seed를 함께 기록합니다. [PyTorch 재현성 안내](https://docs.pytorch.org/docs/stable/notes/randomness.html)를 확인하세요.
