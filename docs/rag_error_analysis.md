# RAG 실행 결과와 오류 분석

2026-09-20에 RTX 3060에서 실행한 합성 정책 RAG의 결과를 기록했다. **검색 성능이 좋아도 생성 답변은 틀릴 수 있었다.** 따라서 기본 기능은 검색 근거 원문을 보여 주며, Qwen 생성 결과는 `verified: false`인 별도 초안으로만 제공한다. 실제 운영에 쓰는 정책 답변 시스템이 완성되었다고 주장할 수 없다.

## 실험 조건과 원본

- 정책 16개, 개발 질문 12개(답변 가능/불가 각 6개), 평가 질문 16개(가능 10개, 불가 6개).
- 정책과 QA는 한 작성자가 만든 소형 합성 데이터이다. CJ 계열사의 실제 정책·개인정보·내부 데이터는 없다.
- 개발 질문만으로 거절 임계값 `0.14116655162035183`을 정했다. 검색된 상위 3개 문서 중 최대 IDF 가중 질문 토큰 일치율이 임계값을 초과해야 통과한다. 실제 기업 이름을 묻는 질문은 별도 범위 검사로 거절한다.
- 개발 목적함수는 `답변 가능 질문 통과율 - 2 × 답변 불가 질문 오통과율`이다. 동점이면 높은 임계값을 선택한다. 확률 보정 또는 사실성 판정이 아니다.
- E5: `intfloat/multilingual-e5-small`, revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`. 공식 모델 카드의 `query:`/`passage:` 접두사, attention mask를 적용한 평균 pooling과 L2 정규화를 사용한다. 최대 512토큰이다. [공식 모델 카드](https://huggingface.co/intfloat/multilingual-e5-small)
- Qwen: `Qwen/Qwen2.5-1.5B-Instruct`, revision `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`. CUDA FP16, greedy decoding, 최대 256 생성 토큰, 추가 학습 없음. [공식 모델 카드](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct)
- 모델과 토크나이저는 고정 revision을 사용한다. 모델 로드는 `use_safetensors=True`, `trust_remote_code=False`이며, 기본 실행은 로컬 캐시만 사용한다.
- 이 분석은 저장된 출력과 근거 문서를 대조한 **AI 보조 정성 검토**이다. 독립적인 사람 평가나 자동 사실성 벤치마크 점수로 해석하지 않는다. `metrics.json`의 `human_factuality_review: not_performed` 표시는 그대로 유지한다.

원본 결과: [BM25](../artifacts/rag/bm25/metrics.json), [Dense](../artifacts/rag/dense/metrics.json), [Hybrid](../artifacts/rag/hybrid/metrics.json), [12개 생성 초안이 포함된 전체 평가 기록](../artifacts/rag/hybrid/per_query.json).

## 검색과 거절 결과

| 방법 | Recall@1 | Recall@3 | Recall@5 | MRR@3 | 답변 가능 질문 통과 | 답변 불가 질문 거절 |
|---|---:|---:|---:|---:|---:|---:|
| BM25 | 0.90 | 1.00 | 1.00 | 1.00 | 10/10 | 4/6 |
| E5 dense | 0.90 | 0.95 | 1.00 | 1.00 | 10/10 | 4/6 |
| BM25 + E5 RRF | 0.90 | 1.00 | 1.00 | 1.00 | 10/10 | 4/6 |

Recall은 질문별 정답 문서 중 검색된 비율을 평균한다. 복수 문서가 필요한 질문 2개가 있어 Recall@1은 0.90인 반면, 첫 문서가 모두 정답 문서라 MRR은 1.00이다. 답변 불가 질문은 검색 지표 분모에서 제외한다.

세 방법 모두 `eval-015`(개인정보·공동현관 비밀번호 원본 요청), `eval-016`(주소 오류 반송의 환불 수수료 요청)을 거절하지 못했다. 이 질문들은 코퍼스 단어와 겹치지만 요청한 실제 값은 없다. **어휘 일치율은 답변 가능 여부와 다르다.** 개발 세트에서는 답변 불가 6개를 모두 거절했지만 평가 세트에서는 2개가 통과했다. 평가 결과를 본 뒤 임계값이나 QA를 바꾸지 않았다.

최종 Qwen 초안은 위 두 질문에 모두 확인 불가라고 답했다. 그렇더라도 검색 단계의 오통과 2건을 성공으로 덮지 않는다. 반대로 아래 표의 불필요한 생성 거절도 검색 단계의 `abstained` 지표에 반영되지 않는다. 단계별 측정 대상이 다르기 때문이다.

## Hybrid 생성 초안 12개 전수 대조

문서 ID는 모두 버전 `1.0`이다. 사실 일치 여부와 인용 형식 준수 여부를 분리해서 검토했다. 아래의 '일치'는 해당 합성 문서와의 대조 결과이며 실제 기업 규정의 정확성을 뜻하지 않는다.

| 질문 ID | 근거 및 기대 내용 | 저장된 초안 검토 |
|---|---|---|
| eval-001 | OPS-002: 영하 15도 초과 5분, 출고 보류, 냉동 설비 점검 | **오류·누락.** 냉동 질문에 냉장 정책 OPS-001의 격리·품질 담당자 절차를 섞었다. 5분 기준과 출고 보류·설비 점검을 빠뜨렸다. 인용 없음. |
| eval-002 | OPS-006: 주소 재확인까지 배차 보류 | **불필요한 거절.** 정답 문서가 1위로 검색되었는데 확인 불가라고 답했다. |
| eval-003 | OPS-008: 두 담당자 독립 재검수, 계속 불일치하면 확정 보류 | 주요 내용이 문서와 일치한다. 원본 스캔 수정 금지도 일치한다. **인용 없음.** |
| eval-004 | OPS-009: 오후 3시 마감 이후 변경은 다음 영업일 검토 | 오후 4시를 마감 이후로 처리한 결론이 일치한다. **인용 없음.** |
| eval-005 | OPS-012: 실제 지연 여부가 확정된 표본만 성능 계산에 사용 | **반대 답변.** 초안은 실제 지연 여부가 없는 배송도 사용한다고 했다. 함께 언급한 재배포 검토는 문서에 있지만 핵심 오류를 상쇄하지 않는다. 인용 없음. |
| eval-006 | OPS-015: 봉인 훼손 반품 자동 전환 금지, 품질 판정 대기 | **불필요한 거절.** 정답 문서가 1위로 검색되었는데 확인 불가라고 답했다. |
| eval-007 | OPS-016: 위험물과 일반 식품의 동일 적재 구역 배치 금지 | **반대 답변.** 초안은 같은 구역에 넣어도 된다고 했다. 실제 위험물 법규라는 제공되지 않은 예외처럼 읽히는 표현도 추가했다. 인용 없음. 안전 관련 실제 업무에 사용할 수 없음을 보여 준다. |
| eval-008 | OPS-014: 후속 스캔 없이 24시간 경과 + 도착 예정 시각 초과 | 두 조건을 함께 제시하여 문서와 일치한다. **인용 없음.** |
| eval-009 | OPS-001: 2~8도, OPS-011: 센서 관측 15분 누락 | 숫자가 모두 일치하고 두 문서 인용이 있다. 다만 첫 문장에 두 사실을 합친 뒤 OPS-001 인용을 붙여 사실별 출처 연결은 명료하지 않다. 유일한 인용 형식 통과 사례이다. |
| eval-010 | OPS-004: 주문 번호 마지막 네 자리, OPS-010: 이름·전화번호·상세 주소 제외 | **불필요한 거절.** 필요한 두 문서가 모두 상위 3개에 있는데 확인 불가라고 답했다. |
| eval-015 | 실제 전화번호·비밀번호 원본은 코퍼스에 없음 | 검색 단계는 오통과했으나 **초안은 확인 불가라고 거절**했다. 개인정보를 만들어 내거나 출력하지 않았다. |
| eval-016 | 환불 수수료는 코퍼스에 없음 | 검색 단계는 오통과했으나 **초안은 확인 불가라고 거절**했다. 수수료를 만들어 내지 않았다. |

12개 생성 중 인용 형식 검사 통과는 1개(8.33%)이다. 인용이 없다는 사실이 곧 모든 문장이 거짓이라는 뜻은 아니며, 인용이 있다는 사실도 내용의 정확성을 보장하지 않는다. 위 기록에서는 4개 초안의 주요 답변 내용이 문서와 일치했고, 3개는 오류·누락, 3개는 답할 수 있는데 거절, 2개는 답할 수 없는 질문에 적절히 거절했다. 이는 이 출력 묶음의 정성 분류이며 일반화 가능한 정확도 추정치가 아니다.

## 성능 비용과 해석

| 방법 | 검색 중앙값 | 검색 p95 | 인덱스 생성 |
|---|---:|---:|---:|
| BM25 | 0.181 ms | 0.233 ms | 2.565 ms |
| E5 dense | 7.921 ms | 8.722 ms | 3,329.783 ms |
| Hybrid | 8.407 ms | 10.860 ms | 2,952.170 ms |

Hybrid 생성 중앙값은 약 1,762.910 ms이다. Hybrid + Qwen 실행에서 PyTorch가 기록한 최대 GPU 할당 메모리는 약 3,539.943 MiB였다. 이는 GPU 전체 사용량이나 메모리 예약량이 아니다. 인덱스 생성 시간에는 모델 초기화가 포함되며, 검색 시간은 생성 시간을 포함하지 않는다. 단일 실행·소형 데이터이므로 서비스 지연 SLA를 주장하지 않는다.

이 데이터에서는 BM25와 Hybrid의 Recall@3이 같고 BM25가 훨씬 가볍다. Dense를 붙였다고 성능 개선을 주장할 근거는 없다. 확장하려면 동의어·오타·짧은 질문·상충하는 버전·더 긴 문서가 포함된 새 검증 세트가 필요하다.

## 다음 실험으로 분리할 개선 가설

1. 생성 프롬프트를 개발 세트에서만 개선하고, 부정문 역전·조건 누락·문서 간 규칙 혼합을 별도 검증한다. 평가 세트의 이 실패 문항으로 프롬프트를 조정한 후 같은 점수를 새로운 일반화 성능처럼 보고하면 안 된다.
2. 검색 문서 전체를 섞는 대신 질문에 직접 대응하는 문장과 문서 ID를 구조화해서 제시하는 방식, 사실별 인용을 요구하는 출력 형식, 출처 불일치 시 초안 보류를 비교한다. 구조화 출력 자체가 사실성을 해결하지는 않는다.
3. 답변 불가 판정에는 어휘 중첩 외에 요청한 속성·값의 존재 여부를 검토하는 단계를 평가한다. 독립적인 새로운 불가 질문을 추가한다.
4. 추출 근거 화면은 유지하고 생성은 기본으로 끈다. 실제 서비스라면 권한, 문서 버전·유효일, 운영 승인과 독립 평가가 별도로 필요하다.
